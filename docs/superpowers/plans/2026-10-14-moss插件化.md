# MOSS 插件化（`moss-tts` 预装 + 全插件进索引）实施计划

> **For agentic workers:** REQUIRED SUB-SKILL：用 superpowers:executing-plans 逐任务实现。步骤用 `- [ ]` 跟踪，**每完成一项即把对应 `- [ ]` 改成 `- [x]`**。
> 设计依据：`docs/superpowers/specs/2026-10-14-moss插件化-design.md`。

> **状态（2026-10-14 定）：本项采用路径①——MOSS 插件化放至 fish 合入之后（P5 后、P6 前），在 main 上做，复用 fish 已带的通用 `plugin_custom_voices` 机制。**
> 原 Task 1（moss 迁移分支）已回退（`1c17f1d`）：因为“moss→moss-tts”重定向必须与 moss-tts 插件+预装+前端面板**原子同落**，否则先上 main 会把老用户指向不存在的插件。“逐引擎先调查音色机制”立为本类工作硬前提（见下）。

**Goal:** 把内置 MOSS 引擎改造成预装插件 `moss-tts`，本体不再有任何内置 TTS 引擎；老用户 key/音色自动迁移、装好即用不变；所有引擎插件同时进在线索引。

**Architecture:** 仿 mimo-tts 插件化：新建 cdylib crate（`va_tts_plugin!` 非流式，读 `MOSS_TTS_API_KEY` env）→ 打包进 `resources/plugins` 预装 + 进索引 → 宿主删内置 `tts/moss.rs` 与 `"moss"` 分支 → `migrate_legacy_engine` 增 `moss→moss-tts`（key→`plugin_config`、voice→`plugin_voices`）→ base-hygiene 更新基线。

**Tech Stack:** Rust（插件 C ABI + 宿主 commands/plugins/storage）、React/TS（设置/音色面板）、PowerShell（package/publish/verify-index）、既有 edge/mimo/minimax 插件范式。

## 🧭 关键发现：通用「我的音色」机制 fish 线已实现——B 应复用、不重造

【重大发现——B 的正确姿势与排序】通用「我的音色」机制 **fish 线已完整实现**：`settings.plugin_custom_voices: Record<插件id, CustomVoiceItem[]>` + 通用 `CustomVoicePanel`（增/选/删）+ `VoiceSynthPanel` 下拉“内置/我的”两 optgroup；插件无需特处理（选中自定义 id 经 `voice` 参数原样透传）。
→ **B 不重造轮子，而是复用 fish 这套**；MOSS 做它的第二个用户（验证通用性，止好契合“以后多自定义音色插件”的目标）。但本树与 fish 各写一份 `plugin_custom_voices`/`VoiceSynthPanel` 会在 **P4 合并时正面对撞**（总账 §P4 已预警）。
→ **排序选择（需用户定）**：
  - **路径①（推荐）**：MOSS-B **放到 fish 合入之后**（在 P5 后的 main 上做），直接复用已合入的通用机制→零重复、MOSS-B 燢小（crate + 迁移 moss_voices→plugin_custom_voices + 接面板）；代价：MOSS 不再是“P3 前”项，而是“fish 合入后”一项（仍在 1.9.0 内）。
  - **路径②**：先把 fish 的**通用音色部分**（`plugin_custom_voices`+`CustomVoicePanel`+`VoiceSynthPanel` optgroup，引擎无关那几笔）挑进本树，再在其上做 MOSS-B；P4 剩余 fish 改动时因同机制冲突变小。代价：需从 fish 拣枝，跨线依赖。
  - **路径③**：本树先独立实现一套同构机制 → P4 再与 fish 合并去重（冲突最大，不推荐）。
