## 五、已知风险（诚实列出）

1. 克隆音色首响在服务端兼容模式下本就是"全文推完"，`stream_open` 打点只能**定位**多出的 40 秒在
   建会话还是等服务端，不能让它变快；若结论是"我们这边"，需单独修（会推迟发布）。
2. fish 免费档限 **2.9 次/分 · 1 并发**，连调会短暂 402（自恢复）；用户手册要写清。
3. fish 的 WS `tts-live` 协议实测握手异常，其流式是 HTTP chunked 路线——与 MiMo/MiniMax 三条流式实现并存，
   播放管线（`StreamPlayer`）第一次要同时伺候三种块节奏，验收需覆盖三家。
4. 老用户升级清理（P2）如果漏做，`<exe>/plugins/minimax-tts` 会与 stream 并存，表现为"两个 MiniMax 国内版"。
5. `v1.8.8` 那笔半途发版留下的现象（tag 存在但版本未 bump）说明发布链可能有步骤没走完；P6 前应先核

### Task 15：流式「即发即入框 + 可静音」全路径统一（真机验收 P1 抖出的主缺陷）

用户定的语义（**注意：不是“中止合成”**）：点停止 = **只静掉扩声器与虚拟麦克风的播放**，
**合成继续跑完、消息照常入列表、音频文件照常产出**，只是不再响。

1. Rust：`StreamPlayer` 新增“静播”控制（Mute）——只停 sink，**不 Abort 会话、不停拉块**，
   文件继续写完整；与现有 Abort 语义区分开（遥控/抢占旧流仍用 Abort）。
2. Rust：消息 id 与 `audio/{fid}.wav` 路径的分配**提前到 `stream_start` 之前**，抽出纯函数
   （`plan_stream_paths` 类）便于单测；会话建立成功后 emit `tts:streaming`
   `{id, content, audio_path, engine, created_at}`。
3. 前端：订阅 `tts:streaming` → 立即插入**占位气泡**（清空输入框、置底）；占位气泡带
   「⏹ 静播」按钮调 `tts_stream_mute`，**重播/收藏暂禁用**（wav 未写完，对应 Task 9-M-3 的已知隐患）；
   命令返回后用同 id 原地换成正式消息；失败则占位气泡转错误态（不静吞）。
4. 消除双播：把宿主在播的 `audio_path` 经现有 `va:play:start`/`playback:started` 同步到前端 `playingPath`；
   `playAudio` 起 `<audio>` 前先静掉宿主（否则同一消息两路声音重叠）。
5. 全路径统一：主窗发送、语音输入直接发送、浮窗 QuickInput、手机遥控发字——事件由后端发，
   各窗口只是订阅者（用户已选定全路径）。
6. 非流式引擎（MOSS/Edge/Genie/Hojo）行为不变：不发 `tts:streaming`，走原有“完成后自动播”。
7. 测试：Rust 路径预分配/事件载荷纯函数单测 + “静播不终止合成”状态单测；前端占位气泡
   状态机（streaming→done/muted/error）抽纯函数 + vitest。门禁全量复跑 + 真机复验
   （出声前气泡已在、点静播后不再响但消息仍落库、点气泡不双播）。

### Task 16：麦克风设备失败的日志可读化（方案 A）

同一设备连续失败**只 warn 一次**，文案保留原错误码并附中文翻译：
`无法打开设备 CABLE Input（VB-CABLE）：0x8889000A —— 该设备正被其他程序独占（常见于远程控制/录音软件），
请关闭占用者，或在声音设置的设备高级属性里取消“允许应用程序独占控制该设备”`。行为不变。

取证记录：`0x8889000A = AUDCLNT_E_DEVICE_IN_USE`；本机会话内**流式与非流式两条路径都失败**
（`mic.rs` 常驻路径也报同码，见 p1.log 01:19:57 / 01:22:10 / 01:47:54 / 01:52:49），
故“我们对同一设备双开”假设已被否证；rodio `try_from_device` 是共享模式，我们从不请求独占。

### Task 17：插件数据目录对齐（只对齐 data，dll 仍隔离）

背景：插件根由 `resolve_plugins_root()` 单点解析（`VA_PLUGINS_DIR` > exe 同级 `plugins/`），
本地引擎的模型/音色在 `<插件目录>/data/`（经 `VA_PLUGIN_DATA_DIR_<ID>` 告知），
故多工作树 / debug / release 各一套 ⇒ genie 环境“看起来丢了”，重下要几 GB。

- 新增解析：`VA_PLUGIN_DATA_ROOT`（或后续再提设置项）——有值时数据目录用
  `<root>/<插件 id 化的名字>/data`，无值时保持 `<插件目录>/data` 不变（**默认行为零变化**）。
- 三个 `load_*` 路径（TTS/ASR/service，均在 loader.rs 同一函数样式）收敛成一个 helper，避免三处不一致。
- 单测：env 存在/缺失两种下的路径推导；不同 id 连字符→下划线映射。
- 文档：写清取舍——共享 data 后**不同分支会互踩模型格式/版本**（dll 仍隔离，所以插件代码不会串），
  并说明为何不把插件根默认改回 APPDATA（阶段 22 刚从那里搬出去，理由是系统盘空间；
  往回改要迁移几 GB 模型，属破坏性变更，不在本版）。
- `VA_PLUGINS_DIR` 作为“开发期临时对齐”手段写进 skill/AGENTS 的开发环境一节（零代码，
  但要警告 dll 版本会跨分支互串，仅作临时手段）。
