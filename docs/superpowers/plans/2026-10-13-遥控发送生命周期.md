# 遥控发送生命周期（手机发送 = 后端替 PC 走一遍标准发送）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现本计划。步骤用 `- [ ]` 复选框跟踪。

**Goal:** 让"从手机 App / 网页遥控器发出的消息"在 PC 各窗口获得与"PC 本地发送"完全一致的气泡生命周期——**输入即出占位气泡 → 成功转正式消息 / 失败转可重试失败气泡**，且**与引擎流式/非流式无关**。

**Architecture:** 后端 `remote::server` 收到 `synthesize` 命令时，即刻以「文本内容」为键向所有窗口广播一条 `tts:send-started`；失败时广播 `tts:send-failed {content, reason}`。成功无需新事件——沿用现有 `message:changed`→`chatStore.mergeLatest`，并给 `mergeLatest` 增加"并入真实消息时收掉同内容占位"的规则。前端 `chatStore` 新增 `remotePending`，并把 `remoteFailed` 改为"优先把同内容占位转失败、无占位才补一条"。所有匹配按 **content** 去重，流式引擎的 `tts:streaming`（带真实 id）仍走原 `adoptStreaming`，互不冲突。

**Tech Stack:** Tauri v2 + Rust（`src-tauri/src/remote/server.rs`、`plugins/bridge.rs`、`commands/tts_stream.rs`）；React/TS + zustand（`src/App.tsx`、`src/stores/chatStore.ts`）；Flutter（`remote-app/`，App 侧错误提示 UX）。

## 一、根因（真机日志证实，非推演）

手机选"未安装/未下载音色"的 hojo-tts 发送，PC 无气泡、手机 toast 被输入法遮挡且秒消失。后端诊断日志（2026-10-13 加入）：

```
[08:29:11.051 INFO ] [remote] 收到 synthesize：len=6
[08:29:11.053 WARN ] [remote] synthesize 失败：网络请求失败: 音色「demo-male-zh」尚未下载，请到 设置 → 音色管理 中安装后再试
```

结论：
- 命令**已到达后端并正确报错**（排除"命令没送进来"）。
- `native_synthesize` 拿到 `Err` 后只通过 WS `ack` 回了手机，**从未向 PC 窗口广播任何事件** → PC 前端 `remoteFailed` 收不到 → 无失败气泡。
- **成功**的手机发送靠 `message:changed`→刷新才冒气泡（有合成耗时延迟、无即时占位）；**失败**彻底无声。
- 手机侧：`ack.err` 能弹 toast（App 源码 `sendText` 有 `if(!ack.ok) showToast`），但 **toast 位于输入法之下 + 2.5s 自动隐**，属 UX 缺陷。

**关键澄清（推翻早期误判）：** "即时占位"与引擎流式与否**无关**。PC 本地发送对流式/非流式都先 `beginPlaceholder` 再结算。手机发送不即时，是因为"发送由后端代跑、PC 前端那段占位代码没触发"，故修法＝**后端把这条发送的生命周期广播给 PC，PC 按内容渲染**，非流式靠 `mergeLatest` 收占位、无需 `tts:streaming`。

- [ ] **Step 3: 实现 chatStore**

在 `src/stores/chatStore.ts` 的 `ChatState` 接口加：

```ts
/** 遥控/跨窗发送到达：按内容追加一条“合成中”占位（同内容已有则跳过） */
remotePending: (content: string) => void;
```

`remoteFailed` 保持签名 `(content: string, reason: string) => void`，但**改为转态优先**（见下）。实现：

```ts
remotePending: (content) =>
  set((s) => {
    const c = content.trim();
    if (!c) return {};
    // 同内容已有“合成中/失败”占位（本窗发送、或已收到 send-started）→ 去重
    const dup = s.messages.some(
      (m) =>
        m.content === c &&
        (s.streamingIds.includes(m.id) || s.failedIds.includes(m.id)),
    );
    if (dup) return {};
    const id = `tmp_${Date.now()}_${Math.random().toString(36).slice(2, 8)}`;
    return {
      messages: [...s.messages, { id, content: c, audio_path: "", created_at: new Date().toISOString() }],
      streamingIds: withId(s.streamingIds, id),
    };
  }),

remoteFailed: (content, reason) =>
  set((s) => {
    const c = content.trim();
    // 1) 命中同内容的“合成中”占位 → 原地转失败（不新增，保持位置）
    const idx = s.messages.findIndex(
      (m) => m.content === c && s.streamingIds.includes(m.id),
    );
    if (idx >= 0) {
      const id = s.messages[idx].id;
      return {
        streamingIds: withoutId(s.streamingIds, id),
        failedIds: withId(s.failedIds, id),
        reasons: { ...s.reasons, [id]: reason || "" },
      };
    }
    // 2) 同内容已是失败态 → 不重复补
    if (s.messages.some((m) => m.content === c && s.failedIds.includes(m.id))) return {};
    // 3) 无占位（极少：send-started 丢失）→ 补一条失败气泡
    const id = `tmp_${Date.now()}_${Math.random().toString(36).slice(2, 8)}`;
    return {
      messages: [...s.messages, { id, content: c, audio_path: "", created_at: new Date().toISOString() }],
      failedIds: withId(s.failedIds, id),
      reasons: { ...s.reasons, [id]: reason || "" },
    };
  }),
```

`mergeLatest` 内，在计算 `locals` 之前/之中加"同内容收敛"：真实列表里出现的、有非空 `audio_path` 的内容，若窗口内有一条同内容的**合成中占位**（在 `streamingIds` 且 `audio_path===""`），则该占位不再保留（视为已被正式消息取代）。示例（并入现有 mergeLatest 逻辑）：

```ts
mergeLatest: (list, hasMore) =>
  set((s) => {
    const inWindow = new Set(list.map((m) => m.id));
    // 真实消息（已落库）所含内容——用于收掉同内容占位
    const settledContents = new Set(
      list.filter((m) => m.audio_path !== "").map((m) => m.content),
    );
    const isLocal = (m: Message) =>
      m.audio_path === "" || s.streamingIds.includes(m.id) || s.failedIds.includes(m.id);
    const locals = s.messages.filter(
      (m) =>
        isLocal(m) &&
        !inWindow.has(m.id) &&
        // 关键：非流式成功时，同内容的“合成中”占位被真实消息取代 → 丢弃占位
        !(s.streamingIds.includes(m.id) && settledContents.has(m.content)),
    );
    const settled = new Set(
      s.streamingIds.filter((id) => {
        const m = s.messages.find((x) => x.id === id);
        return !!m && (inWindow.has(id) || settledContents.has(m?.content ?? ""));
      }),
    );
    // …其余保持原实现：older 拼接、streamingIds 过滤 settled、hasMore…
  }),
```

> 注：以现网 `mergeLatest` 真实实现为基线，仅**新增 `settledContents` 过滤**这一条规则；勿改动原有去重/顺序逻辑。若原实现变量命名不同，按等价语义贴合。

- [ ] **Step 1: synthesize 分支加 start/failed 广播**

在 `synthesize` 分支：进入即广播 `tts:send-started`（携带原文），失败时在 `ack` 前广播 `tts:send-failed`。保留已加的诊断日志。

```rust
"synthesize" => {
    let text = msg.get("text").and_then(|v| v.as_str()).unwrap_or("").to_string();
    // 即时让 PC 各窗口按内容画“合成中”占位（遥控发送 = 后端替 PC 走标准发送生命周期）
    let _ = shared.app.emit("tts:send-started", serde_json::json!({ "content": text }));
    log_info!("[remote] 收到 synthesize：len={}", text.chars().count());
    let out2 = out.clone();
    let app = shared.app.clone();
    tokio::spawn(async move {
        let result = native_synthesize(&app, &text).await;
        let (ok, err) = match result {
            Ok(()) => (true, String::new()),
            Err(e) => (false, e),
        };
        if ok {
            log_info!("[remote] synthesize 完成");
        } else {
            log_warn!("[remote] synthesize 失败：{err}");
            // 失败广播给 PC → chatStore.remoteFailed 把同内容占位转失败气泡（可重试）
            let _ = app.emit(
                "tts:send-failed",
                serde_json::json!({ "content": text, "reason": err }),
            );
        }
        if let Some(a) = ack(ref_id.as_deref(), ok, &err) {
            let _ = out2.send(a);
        }
    });
}
```
