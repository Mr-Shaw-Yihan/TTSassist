# 消息发送与播放体验 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: 用 superpowers:subagent-driven-development 或 superpowers:executing-plans 逐任务实施本计划。步骤用 `- [ ]` 勾选跟踪。
> 设计来源：`docs/superpowers/specs/2026-10-13-消息发送播放体验-design.md`

**Goal:** 把主窗发送改成非阻塞（发送即进气泡、状态在气泡、解放输入框），并修好"首启音频不进虚拟麦克风"和"播放按钮不同步/双播"两个缺陷。

**Architecture:** 前端以事件驱动的消息状态机（合成中→完成/失败+重试）替代 `handleSend` 里 `await generateTTS` 的同步等待；后端补发 `tts:failed(id,reason)`、宿主播放开始发 `va:play:start`；打断用现成 `tts_stream_stop`。首启麦克风(F)先加取证日志复现定根因再修。

**Tech Stack:** Tauri v2 + React/TS + Rust；vitest（前端纯函数）、cargo test（后端）；门禁 = `cargo test --lib`、`cargo check --lib --tests --bins`、`npx tsc --noEmit`、`npm run test:run`、`npm run build`、四守卫、`verify-index -SkipDist`。
