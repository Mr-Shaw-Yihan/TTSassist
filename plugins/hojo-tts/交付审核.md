## 一、任务与范围

把上游 [HojoAI/Hojo-TTS-Light](https://github.com/HojoAI/Hojo-TTS-Light) 的 **80M 变体**
（零样本音色克隆，ONNX 纯 CPU 推理，中英混读，Apache-2.0）接入电子声带
（VoiceAssist）作为**本地 TTS 推理插件**，与既有 genie-tts 插件同类同构。

**铁律遵守情况：宿主本体（VoiceAssist/src-tauri 源码）零改动。** 本次工作只新增
`plugins/hojo-tts/` 目录；宿主侧仅使用了既有通用机制（插件安装、registry 注册、
setup/voices 可选符号通道）与打包脚本的既有行为（见 §五"宿主侧文件变化"）。

## 三、运行架构与数据布局

```
VoiceAssist 宿主
  └─ plugin.dll（薄壳：C ABI 八符号 + setup/voices 可选符号）
       └─ python.exe hojo_server.py（子进程，127.0.0.1 随机端口，Job Object 随宿主退出）
            └─ onnx_model.py（上游推理：4 个 ORT session，bf16→fp32 CPU 推理）
```

数据目录 `<exe同级>/plugins/hojo-tts/data/`：

```
python/     embeddable Python 3.12.10 + 推理依赖（实测约 1.2GB）
models/     HF 仓库 HojoAI/Hojo-TTS-Light 快照，8 个必备文件（约 460MB）：
            llm/encoder/decoder/speaker 四个 .onnx + voice.npz
            + config.json + tokenizer.json + tokenizer_config.json
voices/     音色包 voices/<id>/{ref.wav, voice.json}（音色=参考音频+参考文本）
hojo_server.py / onnx_model.py / LICENSE-*.txt   运行期由 dll 写出
hojo-server.log / server-port                     排障
```

合成链路（幂等）：音色已装检查 → Python 环境 → 服务 → 模型 → 引擎预热 →
`POST /tts {voice_id, text}` → 24kHz 单声道 16bit WAV 字节。

## 四、关键设计决策记录（含两轮用户反馈的响应）

1. **依赖裁剪**：不装上游 requirements.txt（torch+cu128/transformers/optimum 为
   GPU 训练向），只装 onnx_model.py 实际 import 的 11 个包。**`onnx` 必须保留**：
   模型 config.json 声明 `dtype: bfloat16`，CPU 推理依赖 onnx 包把权重提升为 fp32
   （上游代码逻辑，缺该包 ORT 加载失败）。
2. **【反馈 1 响应】零用户配置**：初版按文档惯例声明了 manifest config（HF 端点/
   pip 源两项），用户指出电子声带面向大众、配置卡对小白无意义，已全部移除。
   网络容错改为内置：pip 多源回退（清华→腾讯→官方）、模型下载多端点回退
   （hf-mirror→官方）、音色下载双源回退（GitHub raw→jsdelivr）。留无 UI 的
   环境变量后门（`HOJO_TTS_HF_ENDPOINT`/`HOJO_TTS_PIP_INDEX_URL`）供排障。
   min_app_version 随之从 1.8.0 回落到 1.4.0（无 config 声明后与 genie 一致，
   1.4.0 起宿主即支持 setup/voices 符号与 data 目录注入）。
3. **【反馈 2 响应】预置音色全部带参考文本、性别按实测**：
   - 初版 4 个预置音色无参考文本（上游未公开），用户指出无文本预置无意义；
   - 基频实测（自相关 F0 估计，浊音帧中位数）证明 **zh1 实为女声（277Hz）**，
     上游 README 标注 "Code-switching Male Voice" 有误，本插件以实测为准；
   - 参考文本补齐方式：faster-whisper（small, int8, CPU）转写，**用 zh1 做校准
     样本——转写与上游官方文本逐字一致（仅标点差异）**，其余 4 条转写采用；
   - 现预置表（性别=F0 实测）：female-zh-1（默认，文本=官方公开）、
     female-zh-2/3、female-en、male-en（文本=ASR 转写，voice.json 标记
     text_source）。上游 80M 无内置音色库，可用素材仅此 5 个 wav，
     **无中文男声素材**（遗留决策项，见 §七）。
4. **音色机制复用宿主通道**：安装/卸载/预加载/导入走 `va_tts_plugin_voices!`
   四符号（与 genie 同款），无私有音色机制。音色包格式 = 参考音频 + 参考文本，
   即上游零样本克隆的全部输入。
5. **合成不静默下载音色**（阶段 21 语义）：synthesize 先查音色已装，未装报中文
   错误引导；仅 run_setup/install_voice（用户显式触发、进度可见）才下载预置音色。
6. **服务端惰性加载**：启动只 import fastapi（秒级就绪），onnx_model（torch 等
   重依赖）在首次 load_voice/tts 时才构造；合成加线程锁串行（CPU 推理防并发互踩）。
7. **一个实坑修复**：embeddable Python 的 `._pth` 接管 sys.path 不含脚本目录，
   `import onnx_model` 失败；已在服务端显式 `sys.path.insert(0, 脚本目录)`。
